# What this is
Ten Claude Code launch prompts, one per butterfly component primer (PRM-LWC, RWC, CEC, HDC, TXC, ABC, PRB, LBP, LEG, ANT), each written by the house workflow used for PROMPT-P0, PROMPT-A..L and PROMPT-PRM0: lever → prompt → evidence pack → open questions → eval pack → design notes. Each prompt executes *that primer's own imperatives* — the three `TASK-<PFX>-00n` blocks in its §-9 part 4 (exactly three per primer, thirty in all; other TASK IDs in the primers are cross-references), its §-9 part 3 RECON register, its §-9 part 7 HALT triggers made mechanical, its §-8 contracts and properties as tests, and its §-10 execution-field table as a conformance walk — as **new files only**, against **synthetic material only**, on the skeleton the primer names when it exists (`cdss-fabric`, `cdss-compiler`, `cdss-spine`, `cdss-ui-clinician`, `cdss-ui-patient`, `cdss-governance`) and under the run directory `build/<proposed-repo>/` when it does not (`cdss-fuzzy`, `cdss-meta`, `cdss-ui-auditor`, `cdss-infra`, `cdss-dataplane`, `cdss-governance/regulatory-sensing/` — all pending DEC-09). Each stops exactly where the primer's HALT triggers or an OPEN ruling says stop.

Run **PROMPT-PRM0** first: it produces the `CONTRACT-ARG-1_PIN_STATE.md` every one of these runs pastes into its definition-of-ready, the `BUILD_BOARD.md` that lays the thirty tasks across levels, and the `DECISION_QUEUE.md` that names the owner of every ruling these runs will hit.

# Shared laws (every prompt inherits by reference)
PROMPT-P0 §1 laws 1–7: append-only with sha256 bookends and a mandatory empty diff · EXEC-1 precedence for sequencing, corpus / REG-POSTURE for content · delta-reading (REG-SPRINT via 1.1, MET-1 via 1.1, MET-2 via 2.1, R30 via 30.1) · OPEN means OPEN · these are build runs under EXEC-1 D-1 / MET-4 P0 ("L1 on synthetic scope"), not hardening, and write no R29 row · no patient data, licensed text by reference, nothing pushed or deployed · no silent shortcuts (temptations go in HALT_LOG.md).
PROMPT-PRM0 §1 laws 8–11: MAK-FFC v1.1 is host law and the 03_ MANIFEST precedence paragraph rules conflicts after Arch §14 · cite, never re-mint (TASK/RECON/GAP/<PFX>-Fn IDs are interim pending DEC-09) · the posture is cited from `10_regulatory-execution/REG-POSTURE_v1.1.md` (EXEC-1 EX-3; ASSUME-REG-001..008 in §8, 009 minted OPEN in MAK-GOV) and no run closes an ASSUME · the five signals never merge.
Every primer's frontmatter reads `governed_by: "REG-POSTURE v1.0 via MAK-ANT v1.0"` and its epigraph "ASSUME-REG-001..007": every run logs this once as the divergence PROMPT-PRM0 Phase 1 check 1 records, proposes erratum text, and edits nothing.
The One Rule applied to the executor: *every claim is an argument; only arithmetic releases* — the run proposes and tests; it authors no clinical number, membership curve, threshold, codebook word, template, guideline rule, regulatory bearing or ratified schema. Every §-8 "proposed tolerance" is a configurable, flagged-for-sign-off parameter. Every fixture is `FIXTURE-NOT-CLINICAL`.
Status enum everywhere: {DONE-WITH-EVIDENCE, IN-PROGRESS, BLOCKED(reason), ESCALATED(owner), HUMAN-ONLY, NOT-IN-SCOPE}; DoR verdicts {MET, MET-WITH-SUBSTITUTION, PLACEHOLDER, UNMET}; HALT vocabulary {CHAIN-BREAK, DOR-FAIL, SPEC-CONFLICT, ASSUMPTION-REFUTED}. Every run writes to `11_prompts/runs/{{RUN_DATE}}_prm-<pfx>/`, proposes register rows (never writes registers), proposes the `00_MANIFEST.md` §4.4 honesty-line amendment, and tolerates missing sibling outputs by recording a substitution — never by faking the dependency.

# Recommended run order and cross-run dependencies
The order above is the 03_ MANIFEST / RUN-REPORT reading order and is also the dependency order the RUN-REPORT §2.1 edge table implies. Each prompt names what it consumes and emits in its `<siblings>` block, by edge number.

1. **PRM0** — pin state, build board, decision queue. Nothing downstream needs anything else from it, but every DoR quotes its pin-state sentence.
2. **LWC** — emits the type-registry names (μ, activation, defuzzified, Z-reliability; `fit` reserved to RWC) that TASK-CEC-001's DoR requires agreement on, the `GradedGroundAnnotation` and `CrispOrLinguisticGround` shapes TXC/PRB grounds must satisfy (#33/#34), and the two-wing X5 pair PRM-LWC lacks (#12/#14).
3. **RWC** — consumes LWC's degree-type names; emits the PROPOSED `FitReport` and `ConflictRecord` shapes TASK-CEC-002 needs (#8). Seams #15 and #26 stay unmatched and are stubbed as fixtures only.
4. **CEC** — consumes the pin state, LWC's names and RWC's shapes; emits `ReleasedArgument` + stage-trace fixtures with five unblended signals for HDC, TXC, ABC (#16) and the RG-5 schema stub (#17). Unmatched #7, #15, #18, #25, #43 recorded, never closed.
5. **HDC** — consumes #16, RWC envelopes/conflicts (#9), LWC decoder (#2); emits the sign-off record shape TXC's bright line keys on (#22), the face law LBP renders (#21), acts/Deviations for ABC (#20).
6. **TXC** — consumes HDC's sign-off shape (#22), ABC's ODR state shape (#29 — a later run; substitution recorded), LWC decoder (#3); emits grounds (#33/#34), Consult-Prep content (#32), disputes/values/hazards for ABC (#30). PDA API (#36) BLOCKED(unowned).
7. **ABC** — consumes #16/#17, #20, #30, #6, #11; emits obligation status and gate-bundle schemas for ANT (#28) and ODR state for TXC (#29). Its five unclaimed emits (#23–#27) and #44 land as schemas + RECON rows.
8. **PRB** — consumes TXC face law and fixtures, LWC decoder stub (#5), a released-argument fixture (#16); emits the PA-6 bundle for LEG (#40) and grounds fixtures (#34). #35, #36, #37, #45 unmatched.
9. **LBP** — consumes HDC face law (#21), LWC decoder (#5), #16 via fabric; emits acceptance tests for LEG (#39). #38 to HDC unclaimed; #48 overlap ESCALATED.
10. **LEG** — consumes the two conformance suites (#39/#40); #43 (CEC tier manifests) and #44 (ABC retention rules) unclaimed; emits the gateway seam (#41) as a proposal only, ops metrics (#42), stack defaults (#45, LEG8 binding map — no X5 row).

Each prompt tolerates missing siblings: the DoR verdict becomes MET-WITH-SUBSTITUTION with the placeholder named, and the substitution is a RECON row — nothing fakes a dependency.
